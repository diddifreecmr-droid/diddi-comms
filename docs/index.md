# DiddiComms Documentation

DiddiComms is the communication entry point for the DiddiFree application. It
owns task conversations, user-visible messages, external call-attempt logging,
realtime delivery, communication audit, and the frontend facade for Support.

## Start Here

- Frontend teams should begin with the
  [Support integration brief](frontend/DIDDICOMMS_FRONTEND_SUPPORT_BRIEF_2026-10-28.md).
- Module teams should read the [integration overview](integrations/README.md)
  and the [DiddiConnect standard](diddiconnect/DIDDICONNECT_INTEGRATION_STANDARD_V1.md).
- Operators should use the [operations runbook](OPERATIONS_RUNBOOK.md) and the
  [Docker documentation deployment guide](MKDOCS_DOCKER.md).

## Public Surfaces

| Surface | Purpose |
|---|---|
| DiddiComms API | User chat, support conversations, call-attempt logging, and realtime events |
| DiddiComms documentation | Human-readable contracts, integration briefs, and operations guides |
| OpenAPI `/docs` | Interactive HTTP API reference generated by FastAPI |

The MkDocs service is documentation only. Frontends must call the DiddiComms
API, never the documentation container and never another module's internal
routes.
